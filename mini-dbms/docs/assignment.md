# 미니 DBMS 구현 (과제 원문)

## 과제 개요
- 세 단계에 걸쳐 "동작하는 미니 DBMS"를 직접 구현합니다.
  - Phase 1: SQL 처리기 (CLI + 파일 기반 저장)
  - Phase 2: B+ 트리 인덱스 (대규모 데이터 삽입 + 성능 비교)
  - Phase 3: 미니 DBMS — API 서버 (Thread Pool 기반 병렬 처리)
- Phase 2는 Phase 1의 SQL 처리기를 그대로 활용합니다.
- Phase 3은 Phase 1 + Phase 2를 내부 DB 엔진으로 두고, 외부 클라이언트가 호출 가능한 API 서버로 감쌉니다.

## Phase 1. SQL 처리기
- 이번 단계 과제는 'SQL 처리기' 구현입니다.
- 텍스트파일로 작성된 SQL 문을 Command Line 명령을 통해 SQL 처리기에 전달할 수 있어야 합니다.
- SQL 파싱
  - 입력된 SQL 문장을 분석하여 구조화합니다.
  - 최소 지원: INSERT, SELECT
- 실행 (Execution)
  - 파싱된 결과를 기반으로 실제 동작을 실행합니다.
  - INSERT: 데이터를 파일에 저장
  - SELECT: 파일에서 데이터를 읽어서 출력
- 데이터 저장 (File 기반 DB)
  - 각 테이블은 파일로 관리합니다.
  - 요구사항: INSERT → 파일에 데이터를 추가 / SELECT → 파일에서 데이터 읽기
  - 데이터 저장 포맷: 자유롭게 설계 (CSV / binary / custom 등)
- 전체 조건
  - schema 및 table은 이미 존재한다고 가정
  - 즉, CREATE TABLE은 구현하지 않아도 됩니다.

## Phase 2. B+ 트리 인덱스
- 이번 단계 과제는 'B+ 트리 인덱스' 구현입니다.
  - 실제 DBMS에서 사용하는 디스크 기반 B+ Tree를 단순화한 메모리 기반 방식으로 구현합니다.
- 테이블에 레코드가 추가되면 ID가 자동으로 부여되며, 해당 ID를 B+ 트리에 인덱스로 등록해 ID 기반 검색 시 B+ 트리 인덱스를 활용할 수 있도록 만듭니다.
- 대규모 데이터 삽입 후 성능 테스트를 진행합니다.
  - 최소 1,000,000개 이상의 레코드를 Insert 합니다.
  - ID 기준 SELECT (인덱스 사용)과 다른 필드 기준 SELECT (선형 탐색) 간의 속도 차이를 비교해 보세요.
- Phase 1에서 구현한 SQL 처리기를 그대로 사용하여 연동합니다.

## Phase 3. 미니 DBMS — API 서버
- 이번 단계 과제는 '미니 DBMS — API 서버'를 구현하는 것입니다.
- 구현한 API를 통해 외부 클라이언트에서 DBMS 기능을 사용할 수 있어야 합니다.
- 스레드 풀 (Thread Pool)을 구성하고, 요청이 들어올 때마다 스레드를 할당하여 SQL 요청을 병렬로 처리해야 합니다.
- Phase 1에서 구현한 SQL 처리기와 Phase 2의 B+ 트리 인덱스를 그대로 활용하여 내부 DB 엔진을 구성합니다.

## Phase 간 연계 요약
| 단계 | 의존 | 핵심 결과물 |
|---|---|---|
| Phase 1 | — | CLI로 INSERT / SELECT가 동작하는 파일 기반 SQL 처리기 |
| Phase 2 | Phase 1 | Phase 1 처리기 + B+ 트리 인덱스 + 100만 건 성능 비교 |
| Phase 3 | Phase 1 + Phase 2 | Phase 1+2를 내부 엔진으로 사용하는 API 서버 + Thread Pool 병렬 처리 |

## 공통 학습 원칙
- "학습"보다는 "구현"이 우선입니다. AI 등을 적극적으로 활용하여 결과물을 만들어내는 것이 최우선 목표입니다.
  - 다만, 만들어진 결과물 중 핵심 로직에 대해서는 이해하고 설명할 수 있어야 합니다.
  - 코드를 직접 작성하기 어려운 경우, 전체 코드를 AI를 통해 생성해도 괜찮습니다. 다만, 생성된 코드를 반드시 학습하고 그 원리를 이해해야 합니다.
- 추가적으로, 다른 팀과의 차별점을 둘 수 있는 추가 구현 요소에 대해서도 함께 고민해 보시기 바랍니다.

## 중점 포인트
### Phase 1 — SQL 처리기
- SQL 문장을 읽고, 파싱하고, 실행하는 '처리기(Processor)'를 만드는 것
  - 입력(SQL) → 파싱 → 실행 → 저장
- 파일 기반 데이터 저장 방식 설계
- DB 처리 흐름 이해
- CLI (Command Line Interface) 구현

### Phase 2 — B+ 트리 인덱스
- WHERE id = ? 조건일 때, 어떻게 B+ 트리를 사용할 수 있을지
- 대용량 레코드를 쉽게 생성하고 테스트할 수 있는 방법
- Phase 1에서 만든 SQL 처리기와의 매끄러운 연결

### Phase 3 — API 서버
- 멀티 스레드 동시성 이슈
- 내부 DB 엔진과 외부 API 서버 사이 연결을 설계
- API 서버 아키텍쳐
