## 진행 방식 (레디스와 같음)
큰 그림·이유 → 진훈 기대값 → AI 구현 → 실행·비교 → 진훈 설명 → 커밋
- 처음 보는 개념은 "보기 → 따라 말하기 → 기대값" 순서
- **기초 점검 (11/17 진훈 요청)**: Phase 시작마다 ① 검증에 필요한 기초 3개 안팎을 이름 붙여 보이고 ② 질문 하나씩으로 있는지 확인하고 ③ 없으면 15분 안쪽으로 쌓는다
- **검증은 언제·무엇을·어떻게를 명시**: 언제 = 실행 전 기대값 / 실행 후 비교 / 커밋 전 설명, 무엇을 = 핵심 로직·경계와 에러·숫자, 어떻게 = 기대값 비교·테스트·일부러 깨 보기
- **먼저 쓰기 + 가르쳐 보기 (11/17 진훈 채택)**: Claude가 설명·핵심 문장을 쓰기 전에 진훈이 2분 먼저 쓴다(막히면 힌트 하나, 대신 완성 안 함). 단계 끝마다 진훈이 설명하고 Claude는 증거(실행·테스트)로 채점한다
- **질문 주차장**: 질문이 여러 개면 가장 급한 하나에 답하고, 나머지는 progress.md "질문 주차장"에 적는다
- 어려움은 OK, 고통은 X: 2분 버티기 → 힌트. 지치면 쉬기 제안
- 이해는 두 종류 (11/17 진훈 요청으로 기록): **무엇·왜·끝 조건**은 구현 전에, **어떻게**는 만들면서. "완전히 이해"를 기다리며 멈추지 않는다
- 새 파일을 만들면 파일 이름과 역할을 한 줄씩 보여 준다
- 비유와 정확한 용어는 짝으로 쓴다

## No AI Slop 규칙 (11/14 진훈 채택)
1. AI가 한 번에 쓰는 코드 양을 줄인다. 진훈이 검토할 수 있는 양만 쓴다.
2. 같은 실수는 기계가 잡게 한다: `-Wall -Wextra -Werror` + `-fsanitize=address,undefined`
3. ❔를 오래 두지 않는다. 단계가 끝날 때마다 실행으로 ✅ / ❌ 판정한다.
- 공유할 글에는 ✅(진훈이 설명 가능) / ❔(AI 초안, 미확인)을 표시한다.
