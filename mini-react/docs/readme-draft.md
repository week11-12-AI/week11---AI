## React 원리
- ✅ react는 저장한 상태로 렌더링한다
- ✅ 상태가 변했을 때, 변한 것만 업데이트한다
  - ❔ 효율적인 이유: 실제 DOM을 고칠 때마다 브라우저가 다시 계산하고 다시 그린다 (Reflow / Repaint)
  - ✅ JS가 DOM을 첨삭 → 브라우저가 reflow → 브라우저가 repaint
- ✅ 함수(안)로 상태를 저장하지 않는다
- ✅ 상태를 hooks에 두는 이유는, 컴포넌트마다 상태를 저장하기 위해서다
  - ❔ 값 하나를 전역에 두면 카운터 두 개가 같이 올라간다 (냉장고 비유: 아파트 공용 게시판 vs 집마다 냉장고)
  - ❔ 컴포넌트 = 화면 조각 하나 (카운터 하나, 할 일 한 줄). 비유로는 "집 하나"

## 검증 레이어 1바퀴 ("완료된 일 지우기")
- ✅ 요구 카드 → 기대값 설정
- ✅ 기대값 판정 → 실험으로 실제값을 도출해서, 기대값과 비교: 같을 때까지 기대값 또는 코드를 수정
- ✅ 레드팀 → 시스템의 허점(예외)을 찾으려고 노력
- ✅ PR 리뷰 → 첨삭된 코드를 검토 (만약 코드 못 읽으면, 코드 실행된 결과인, 동작 테스트로 대체)
- ✅ 커밋 → 커밋 메시지에 과정을 요약
