# 주소창부터 화면까지, 그리고 React의 자리

> Claude 초안 → 11/11 진훈이 읽고 기록·공유하기로 함

## React의 목적 두 가지
| 목적 | 뜻 | 한 줄 |
|---|---|---|
| **1. 편하고 정확하게** (주된 목적) | 개발자는 **상태만 바꾸면**, 화면은 React가 알아서 맞춰 준다. DOM을 손으로 고치다 어긋나는 일을 막는다 | react는 저장한 상태로 렌더링한다 |
| **2. 효율적으로** | 맞춰 줄 때 **바뀐 곳만** DOM을 첨삭해서 브라우저의 일(③)을 덜 늘린다 | 변한 것만 업데이트한다 |

DOM을 손으로 아주 잘 고치면 React보다 빠를 수도 있다. React의 진짜 가치는 1번을 하면서도 2번 덕분에 충분히 빠르다는 데 있다.

## 전체 그림
```
① 네트워크: 페이지 가져오기                                  (네트워크 담당)
   URL 입력 → DNS → TCP/TLS 연결 → HTTP 요청 → HTML, CSS, JS(React 포함) 받음

② 파싱 + 첫 화면 만들기                                       (메인 스레드)
   HTML ──▶ DOM 트리          CSS ──▶ CSSOM 트리
   JS 실행 → React가 첫 화면을 만듦 = mount
             (컴포넌트 → VNode → createDom → DOM에 통째로 붙임)

③ 렌더링 파이프라인: 트리를 픽셀로                             (브라우저의 일)
   스타일 계산 → 레이아웃(reflow) → 페인트(repaint) → 합성 → 화면
   └──── 메인 스레드 (CPU) ────┘   └ 픽셀 찍기·겹치기: GPU가 도움 ┘

④ 상호작용 루프: 클릭할 때마다                                 (메인 스레드)
   클릭 → 등록해 둔 함수 → setState(상태 바꾸기 + 다시 그리기)
        → 컴포넌트 함수 다시 실행 → 새 VNode → diff → applyPatches
        = React가 update: DOM을 바뀐 곳만 첨삭
        → ③으로: 브라우저가 reflow → repaint (바뀐 곳 근처만)
```

## 관찰 포인트
1. ①②는 **처음 한 번**, ③④는 클릭할 때마다 **반복**된다.
2. **React는 JS 프로그램**이다. 활동하는 곳은 ②(mount: 통째로)와 ④(update: 바뀐 곳만)다. ①과 ③에는 없다.
3. **JS가 DOM을 첨삭 → 브라우저가 reflow → 브라우저가 repaint.** 주어가 다르다.
4. 메인 스레드는 **직원 한 명**이다. JS 실행과 reflow·repaint를 번갈아 한다. 그래서 JS가 오래 돌면 화면이 버벅인다.
