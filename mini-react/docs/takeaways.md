# 미니 리액트에서 다음 과제로 가져갈 것

> Claude 초안 → 11/11 진훈이 훑어보고 전부 공감(✅). A는 레디스·DBMS 주에 실제로 다시 만나면 확인한다.

## A. 기술 아이디어 (레디스·DBMS에서 다시 나올 것)
| | React에서 본 것 | 다시 나올 곳 |
|---|---|---|
| ✅ | **바뀐 것만 반영** (diff → patch) | 레디스 복제: 바뀐 명령만 다른 서버로 보냄 / DB 로그(WAL): 바뀐 것만 기록 |
| ✅ | **계산 결과를 메모하고, 감시 값이 바뀔 때만 다시** (useMemo) | 캐시 = 레디스를 쓰는 이유 그 자체. "언제 메모를 버리나"(캐시 무효화)가 핵심 문제 |
| ✅ | **진실은 한 곳에** (상태는 App에만, 냉장고 목록 하나) | DB: 같은 정보를 두 군데 두면 어긋난다 (정규화) |
| ✅ | **불변식** (history의 지금 칸 = 화면 DOM) | DB: 트랜잭션, 무결성 제약 |
| ✅ | **오래 사는 상자에 맡긴다** (함수는 기억 못 함 → hooks) | 레디스: 프로그램이 꺼져도 남겨야 하는 것 (영속성, 메모리 vs 디스크) |

## B. AI와 일하는 노하우 (어떤 과제에서도)
| | 노하우 | 증거 |
|---|---|---|
| ✅ | 화두 3줄을 매번 묻는다 (무엇이 잘못될 수 있나 / 시간·주의력을 어디에 / 무엇이 맞는지는 내가) | 11/11 |
| ✅ | 검증 레이어: 요구사항 → 기대값 → 레드팀 → 동작 확인 → 커밋 | 1바퀴 완주, 레드팀이 구멍 발견 |
| ✅ | 코드를 못 읽으면 동작으로 검증한다. 대신 "무엇이 맞는지"는 내가 정한다 | PR 리뷰 대체 |
| ✅ | 기대값과 실제값이 다르면, 코드가 틀렸거나 기대값이 틀렸다 | -1 버그 / 버튼 PROPS |
| ✅ | 직접 쓴 건 남고, 읽기만 한 건 샌다. 실험은 파일로 남긴다 | draw·setCount는 기억, 콘솔 실험은 휘발 |
| ✅ | 긴 코드는 접고 입력 → 출력부터 | 따로국밥 해소 |
| ✅ | 낱말이 안 통하면 생활 비유나 C·OS 비유로 | 냉장고 목록, thread_create |
| ✅ | 포지션은 고정한다 (AI = 공격, 나 = 판정) | 포지션 바꿀 때 거부감 |
| ✅ | 바꾸기 어려운 결정을 먼저, 오래 따진다 | 공백 규칙 vs 시연 주제 |
| ✅ | 새 문법이 많으면 계단으로, 조각을 알면 크게 | 계단 1~5 vs useEffect |
