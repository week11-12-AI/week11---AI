## 미니 리액트 구현 — 요구사항

### 과제 개요
- 두 단계에 걸쳐 "동작하는 미니 리액트"를 직접 구현합니다.
  - Phase 1: Virtual DOM + Diff 알고리즘 + Patch
  - Phase 2: 함수형 Component + State + Hooks (useState / useEffect / useMemo)
- 최종 결과물은 사용자의 입력/클릭 등에 따라 **부분 업데이트**되는 동작하는 웹 페이지입니다.

### Phase 1. Virtual DOM + Diff + Patch
- 브라우저의 DOM 정보를 읽어서 Virtual DOM으로 변환하는 함수를 작성합니다.
- 두 Virtual DOM을 비교하여 변경된 부분을 찾아내는 Diff 알고리즘을 작성합니다.
- 검증 웹 페이지: 2개 영역(실제 영역, 테스트 영역) + Patch, 뒤로가기, 앞으로가기 버튼
  - 로드하면 "실제 영역"의 샘플 HTML 코드를 Virtual DOM 트리로 변환하고, 그 Virtual DOM으로 테스트 영역을 렌더링합니다.
  - 사용자가 "테스트 영역"의 샘플 HTML 코드를 자유롭게 수정합니다.
  - Patch 버튼: 테스트 영역 → Virtual DOM → 이전 Virtual DOM과 Diff → 변경된 부분만 "실제 영역"에 렌더링 → 새 Virtual DOM을 State History에 저장
  - 뒤로가기/앞으로가기: state history의 특정 Virtual DOM으로 이동, "실제 영역"과 "테스트 영역"도 함께 변경

### Phase 2. Component · State · Hooks
- **Component**: UI를 나누는 작은 단위. 각자 자신만의 로직과 렌더링을 담당. **반드시 함수형 컴포넌트**.
  - 함수형 컴포넌트를 감싸는 **`FunctionComponent` 클래스**를 직접 만든다. 필요한 기능:
    - `hooks` 배열 (상태 저장용)
    - `mount()`: 처음 렌더링
    - `update()`: 상태 변경 후 다시 렌더링
  - 제약조건 (중요)
    - Hook은 **최상위 컴포넌트에서만** 사용 가능
    - State는 **최상위 컴포넌트(루트 컴포넌트)에서만** 관리
    - 자식 컴포넌트는 state 없이 부모가 준 **props만** 사용 (Lifting State Up). 상태 없는 순수 함수로 구현.
- **State**: 값이 변경될 수 있는 동적 데이터. State가 바뀌면 → 화면이 **자동으로** 다시 그려져야 한다.
- **Hooks**: 함수형 컴포넌트에서도 상태와 생명주기를 쓰게 해 주는 기능. 최소 구현: `useState`, `useEffect`, `useMemo`.
  - 핵심 질문: **"함수는 매번 새로 실행되는데, 상태는 어떻게 유지할까?"**

### Phase 1 ↔ Phase 2 연계
- 상태 변경으로 다시 렌더링할 때 Phase 1의 Virtual DOM을 그대로 활용: Virtual DOM 생성 → 이전과 Diff → 바뀐 부분만 실제 DOM에 Patch.
- 목표: 전체를 다시 그리지 않고 필요한 부분만 업데이트.

### 테스트 페이지 개발
- Phase 1·2를 활용한 브라우저 웹 페이지. 주제 자유. 반드시 사용자의 입력/클릭 등에 따라 화면이 변경되어야 한다.

### 기술 스택 / 제한
- HTML, CSS, JavaScript (또는 TypeScript) — Vanilla. 외부 프레임워크(React, Vue 등) 금지.

### 공통 학습 원칙
- "학습"보다 "구현"이 우선. AI를 적극 활용해 결과물을 만드는 것이 최우선 목표.
- 다만 핵심 로직은 이해하고 설명할 수 있어야 한다. 전체를 AI로 생성해도 되지만 반드시 학습하고 원리를 이해한다.
- 다른 팀과의 **차별점이 될 추가 구현 요소**도 고민한다.

### 중점 포인트
- Phase 1
  - 브라우저에서 DOM을 다루는 방법 (Document, Window)
  - 실제 DOM의 변화를 감지하기 위한 브라우저 API
  - 실제 DOM이 느린 이유 (Reflow / Repaint 관점)
  - Virtual DOM: 구조, 필요한 이유
  - Diff 알고리즘: 동작 방식, 최소 변경을 찾기 위한 5가지 핵심 케이스, 실제 DOM에 반영 방법
  - React에서 실제 DOM을 변경할 때 Virtual DOM과 Diff의 동작 방식
- Phase 2
  - UI를 어떻게 Component로 나눌 것인가?
  - State는 어디에 두는 것이 좋은가?
  - setState는 상태 변경 외에 무엇을 해야 할까?
  - 여러 상태 변경을 한 번에 처리하는 방법은? (Batching — 선택 과제)
  - 이번에 구현한 React와 실제 React의 차이점
