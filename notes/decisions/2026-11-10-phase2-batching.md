# Phase 2 연속 상태 갱신 묶음 처리

- 날짜: 2026-11-10
- 상태: 사용자 선택
- 결정: 한 이벤트에서 상태가 연속으로 변경되면 현재 이벤트 처리가 끝난 후 최신 상태로 한 번 렌더링한다. setter마다 즉시 렌더링하지 않는다.
- 이유: 클릭 처리 후 최신 상태로 한 번 렌더링한다는 설명이 포함된 선택지를 사용자가 선택했다. 별도의 이유는 미기록.
- 대안: setter 호출마다 즉시 렌더링.
- 구현 제안: 슬롯은 즉시 갱신하고 queueMicrotask로 예약하며, 인스턴스당 대기 중인 예약을 하나로 합친다. 구체적 스케줄러 API는 사용자 선택 자체가 아니다.
- 범위: 이 앱의 한 이벤트 안 연속 호출을 묶는 동작이다. React의 전체 자동 batching과 동시성 스케줄러 구현은 포함하지 않는다.
