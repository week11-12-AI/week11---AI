# Phase 1 key 기반 형제 요소 비교

- 날짜 및 상태 — 2026-11-07, 확정
- 결정 — 형제 요소를 key로 대응한다. 초기 요소와 새로 추가한 요소의 key는 자동 생성하고 DOM의 관리용 `data-key` 속성에 저장한다. Virtual DOM과 히스토리에도 key를 보관한다.
- 이유 — 사용자는 자동 생성 및 DOM 속성 저장 방식을 추천에 따라 선택했다. 구체적인 이유는 미기록이다.
- 제안 근거 — DOM에서 Virtual DOM으로 변환할 때 key를 읽고 화면에서 확인하기 쉽다.
- 검토한 선택지 — 자동 생성 후 DOM 속성에 저장, 자동 생성 후 별도 관리, 사용자가 직접 입력
- 미결 사항 — 누락 key 처리, 텍스트 노드 비교, 경로와 이동 작업의 적용 순서
- 추가 결정 — 같은 부모 안에서 key가 중복되면 Patch를 중단하고 중복 요소를 표시한다. 사용자가 새 요소를 선택해 새 key를 부여하고 Patch를 다시 실행한다.
- 이유 — 기존 요소가 무엇인지 확실하게 구분하는 것을 우선한다.
